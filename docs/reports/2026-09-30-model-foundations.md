## Scope and decisions

- `backend/app/generation.py` owns versioned immutable Artifact identity, input/content/provenance hashes, provider-neutral routes, bounded HTTP adapters, per-attempt traces and usage aggregation. `backend/app/evals.py` owns six shared synthetic fixtures and an explicitly opt-in live evaluation path. `backend/tests/test_evals.py` verifies its output and fixture reuse.
- The live path has no implicit credential loading or fabricated prices. It requires an environment key, uses the same schemas and deterministic constraints as the offline evaluator, and emits output hashes rather than generated text. Offline CI continues to use fixture providers without paid calls.
- Domain StoryBible and chapter workflows in later PRs have their own schemas and prompts. Their quality must be judged in those workflow PRs; this foundation probe alone cannot establish it.

## Verified facts

- The locally configured user key authenticates to DeepSeek `/models`, which returned `deepseek-flash` and `deepseek-v4-pro`. A small `ChatProvider.complete` JSON request with `deepseek-flash` returned valid JSON and an explicit `stop` finish reason (70 input and 50 output tokens, 0.912 seconds). No key was committed or included in the report.
- The first live six-fixture probe on the exact PR #25 router passed Pydantic schema validation on **6/6**. Deterministic constraints passed **4/6**. StoryBible represented the correct age as `facts.age` instead of the fixture's `facts.hero_age`; continuity described the age discrepancy in Chinese instead of returning the fixture's `age_mismatch` code. These are real contract mismatches, not schema failures.
- The committed, opt-in `python -m app.evals --live-provider deepseek --live-model deepseek-flash --output ...` path was run on the same fixture hash `f4a307cfe485a3871b7fb16c5b598e57dcab07f6d715be19c48a62e69fb07792`. It passed schema validation on **6/6** and exact constraints on **5/6**; continuity still returned a different violation string. It recorded six attempts, zero retries, 885 input tokens, 1,350 output tokens, 10.785 seconds model latency, 10.793 seconds wall time, no provider price estimate, and no human revision observations. The different first/second outcome shows this model result is not deterministic.
- The shared generic evaluator accepts arbitrary `facts` keys and free-text `violations`; its prompt does not require the fixture's key names or violation codes. The downstream production Bible schema instead has named fields, while the chapter critic has a scored continuity dimension. Therefore the generic key/code failures expose a limit in this probe and do not by themselves prove the downstream workflow has the same defect. Semantic consistency still needs domain-specific live evaluation.
- The five prior PR #25 review threads are resolved; the review concerns explicit finish reasons, logical route replay, Artifact hash integrity, missing table IDs, and non-mapping trace outputs. The owning code and regressions remain in this PR. This report adds no assertion that later code reviews are complete.
