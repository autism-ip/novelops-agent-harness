# ZEN-106 — Model and Artifact foundation review

Date: 2026-09-30 (Asia/Shanghai). Issue [ZEN-106](https://linear.app/zenhungyep/issue/ZEN-106/add-artifact-modelrouter-tracing-cost-and-eval-foundations) / GitHub [#22](https://github.com/autism-ip/novelops-agent-harness/issues/22) is delivered by [PR #25](https://github.com/autism-ip/novelops-agent-harness/pull/25), based on [PR #24](https://github.com/autism-ip/novelops-agent-harness/pull/24), itself based on [PR #23](https://github.com/autism-ip/novelops-agent-harness/pull/23). Merge in dependency order. This is review evidence, not a claim that the full production workflow is deployed.

## Scope and decisions

- `backend/app/generation.py` owns versioned immutable Artifact identity, input/content/provenance hashes, provider-neutral routes, bounded HTTP adapters, per-attempt traces and usage aggregation. `backend/app/evals.py` owns six shared synthetic fixtures and an explicitly opt-in live evaluation path. `backend/tests/test_evals.py` verifies its output and fixture reuse.
- The live path has no implicit credential loading or fabricated prices. It requires an environment key, uses the same schemas and deterministic constraints as the offline evaluator, and emits output hashes rather than generated text. Offline CI continues to use fixture providers without paid calls.
- Backend `Settings` now loads a local `.env.local` after `.env`, with process environment retaining highest priority. This makes the explicitly configured DeepSeek routes available to a normal local backend startup while preserving secret-file Git ignores. A dedicated settings test verifies both precedence boundaries; startup still requires a `BACKEND_API_KEY` and complete enabled runtime tables.
- Domain StoryBible and chapter workflows in later PRs have their own schemas and prompts. Their quality must be judged in those workflow PRs; this foundation probe alone cannot establish it.

## Verified facts

- The locally configured user key authenticates to DeepSeek `/models`, which returned `deepseek-flash` and `deepseek-v4-pro`. A small `ChatProvider.complete` JSON request with `deepseek-flash` returned valid JSON and an explicit `stop` finish reason (70 input and 50 output tokens, 0.912 seconds). No key was committed or included in the report.
- The first live six-fixture probe on the exact PR #25 router passed Pydantic schema validation on **6/6**. Deterministic constraints passed **4/6**. StoryBible represented the correct age as `facts.age` instead of the fixture's `facts.hero_age`; continuity described the age discrepancy in Chinese instead of returning the fixture's `age_mismatch` code. These are real contract mismatches, not schema failures.
- The committed, opt-in `python -m app.evals --live-provider deepseek --live-model deepseek-flash --output ...` path was run on the same fixture hash `f4a307cfe485a3871b7fb16c5b598e57dcab07f6d715be19c48a62e69fb07792`. It passed schema validation on **6/6** and exact constraints on **5/6**; continuity still returned a different violation string. It recorded six attempts, zero retries, 885 input tokens, 1,350 output tokens, 10.785 seconds model latency, 10.793 seconds wall time, no provider price estimate, and no human revision observations. The different first/second outcome shows this model result is not deterministic.
- A production-prompt probe then exposed a route defect: with the prior DeepSeek default thinking mode, StoryBible and chapter critic both timed out at the route's ten-second limit; with a temporary 30-second request timeout, both consumed the full 2,048-token output cap and returned `length`, which the router correctly rejected. DeepSeek's current Chat Completions documentation says thinking is enabled by default. With explicit `thinking: disabled`, the actual chapter critic schema completed in 5.006 seconds and returned `revise` with continuity score 1 on a synthetic 19-versus-20 age mismatch. StoryBible completed in 10.754 seconds with a valid `BibleContent` at 2,048 output tokens, beyond the old ten-second route ceiling. A 1,024-token non-thinking StoryBible probe still truncated.
- The owning ZEN-106 adapter now explicitly disables DeepSeek thinking by default and lets a DeepSeek route opt in. Route timeout may be configured up to 25 seconds, while total request/retry/backoff budget must stay at or below 25 seconds. A post-fix opt-in six-fixture run at 20 seconds / 2,048 tokens passed schema validation on **6/6** and exact constraints on **4/6**, used 735 input and 343 output tokens, 6.398 seconds model latency and zero retries. StoryBible key and continuity code mismatches remain visible. The faster result is evidence about these synthetic calls, not a claim of better story quality.
- After propagating the fix to the domain branches, the actual `ModelRouter`/`ChatProvider` with their production `BIBLE_PROMPT`/`BibleContent` and `CRITIC_PROMPT`/`Critique` pairs passed both schemas on a synthetic story at 20 seconds / 2,048 tokens / no thinking. The generated protagonist retained age 19; the critic identified the deliberately inconsistent age 20, chose `revise`, assigned continuity score 1, and included the age correction in `must_change`. Two calls used 1,160 input and 1,819 output tokens, 12.318 seconds combined model latency, zero retries. This is a targeted prompt/schema smoke check on the descendant code, not an end-to-end persisted workflow or repeated quality evaluation.
- The authorized synthetic [Feishu test Base](https://fcnaul7kb1kf.feishu.cn/base/T8I6buCMoaiLB6srVBrc9i2jnph) now includes full `Artifacts` (`tblx67MsbVEwAxii`) and `Traces` (`tbl7dTKAEzZmlqjX`) tables matching their backend field maps. Field names/types were independently read back; the backend application's own credentials read both empty tables. With the descendant production `BIBLE_PROMPT`/`BibleContent`, a real DeepSeek Flash response passed the schema and `SemanticRuntime.execute` persisted one Artifact and one model Trace through `FeishuClient` → `BaseRepository` → `FeishuStorageProvider`. A same-version replay returned the identical Artifact without a second model call; Artifact readback passed integrity checks and the Trace linked its output ID. Usage recorded one attempt, 487 input/678 output tokens, zero retries, 5.204 seconds model latency and unavailable cost. The full create/replay/read/cleanup sequence took 46.666 seconds. Only rows for probe run `zen106-live-3a13a1bb0c62` were deleted; independent post-cleanup reads found zero rows in both tables.
- The shared generic evaluator accepts arbitrary `facts` keys and free-text `violations`; its prompt does not require the fixture's key names or violation codes. The downstream production Bible schema instead has named fields, while the chapter critic has a scored continuity dimension. Therefore the generic key/code failures expose a limit in this probe and do not by themselves prove the downstream workflow has the same defect. Semantic consistency still needs domain-specific live evaluation.
- The five prior PR #25 review threads are resolved; the review concerns explicit finish reasons, logical route replay, Artifact hash integrity, missing table IDs, and non-mapping trace outputs. The owning code and regressions remain in this PR. This report adds no assertion that later code reviews are complete.
